# TiDE 각도 직접 예측: 목적함수와 인수 설계

## 배경
- 지금 구조(`projects/05_bipv_mismatch/train_tide_mm.py`)는 각도별 성분 50개를 예측한 뒤 `choose_path`(Viterbi)로 각도를 고른다.
- 제안 구조: TiDE가 **하루치 각도 궤적을 한 번에 출력**하고, 손실 함수를 **미스매치 자체**로 둔다(decision-focused learning).
- case2 데이터에는 모든 시점에 10개 각도의 PV·수요 결과가 있으므로, 출력한 각도의 비용을 미분 가능한 형태로 바로 계산할 수 있다.

## 0. 목표: 잉여 구간 경계의 "버퍼" 각도로 미스매치 줄이기

### 제어 구조
- 기본 운전은 **태양고도 추적(θ_ST)** 이다. 아침·오후 부족 구간은 태양추적을 그대로 따른다.
- 태양추적 PV가 수요를 넘는 **잉여 구간**에서만 태양추적을 벗어나 각도를 조절한다.
- TiDE가 줄일 대상은 이 조절 구간과 그 경계에서 생기는 미스매치(구매 + 잉여)다.

### 근거: case3 1/13(IWEC) E+ 실험 (`projects/05_bipv_mismatch/eplus_jan13/`)
- `jan13_surplus90.svg`: 잉여 구간(10:20~14:10)을 90°로 고정하면 큰 잉여는 사라진다.
  대신 **구간 경계에서 PV가 수요 아래로 급락**해 부족이 생긴다(10:20 직후, 13:30~14:10).
- `jan13_a50_10to11.svg`: 시작 경계에 50° 구간(10:00~11:00)을 끼우면 부족이 줄고 잉여가 조금 늘어, 전체 미스매치가 준다.

1/13 07시 ~ 1/14 07시 합계 (kWh, 미스매치 = 구매 + 잉여)

| 운전 | 구매 | 잉여 | 미스매치 | 10~11시 구매/잉여 | 11:00~14:10 구매/잉여 | 14:10~19시 구매 |
|---|---|---|---|---|---|---|
| 태양추적 | 199.54 | 28.28 | 227.81 | 1.27 / 2.40 | 0.34 / 25.88 | 79.58 |
| 잉여 구간 90° | 200.21 | 2.84 | 203.05 | 5.22 / 0.00 | 2.00 / 2.84 | 75.53 |

### 버퍼의 정의
- 버퍼: 태양추적과 90° 사이를 바로 바꾸지 않고, 경계에 **중간 각도(θ_ST < θ < 90°)** 를 두는 구간.
- 경계 근처에서는 PV와 수요 차가 작다. 90°로 바로 넘기면 부족이 생기고, 태양추적을 유지하면 잉여가 생긴다. 중간 각도로 그 사이를 맞춘다.
- 버퍼는 구간 **시작**(10:00~11:00에서 확인)과 **끝**(13:30~14:10, 90°에서 PV < 수요, 미검증)에 모두 둘 수 있다.
  시작 시각 자체도 바뀔 수 있다(50° 실험은 10:20이 아니라 10:00에 시작).
- 한계: 11:30~12:30처럼 90°에서도 PV > 수요인 잉여는 각도로 줄일 수 없다(상한 90°).
- TiDE는 고정된 "잉여 구간 90°" 규칙 대신, **버퍼의 위치·길이·각도를 날짜마다 출력**하는 것이 목적이다.

## 1. 목적함수

결정변수는 하루 144스텝(10분)의 각도 θₜ이다. 날짜 d마다 다음을 최소화한다.

```
J_d(θ) = Σₜ [ w_def · max(Dₜ(θₜ) − Pₜ(θₜ), 0) + w_sur · max(Pₜ(θₜ) − Dₜ(θₜ), 0) ]
         + λ_move · Σₜ |θₜ − θₜ₋₁|
         (− μ · Σ 채광점수ₜ(θₜ), 선택)

제약: θ_ST(t) ≤ θₜ ≤ 90°
```

- Pₜ: PV 발전량, Dₜ: 수요(HVAC 전력 + 조명), θ_ST: 태양고도 추적 각도
- 앞의 두 항은 수요를 목표로 한 **pinball(quantile) 손실**과 같다. τ = w_def/(w_def+w_sur). 1:1이면 Σ|Pₜ − Dₜ|.
  가중치를 바꾸는 것은 τ 하나를 바꾸는 것과 같다.
- **가중치 결정 (2026-11-02)**: w_def = 1로 고정하고 r = w_sur/w_def만 정한다(날짜별 정규화로 전체 크기는 상쇄).
  1차는 **r = 1(1:1)** 로 학습·평가하고, 결과를 본 뒤 **부족에 가중치를 더 주는 방향(r < 1)** 으로 조정한다.
  - 1차 실행: w_sur = 1 고정, **w_def ∈ {1.0, 1.2, 1.4, 1.6}** (w_sur : w_def = 1:1, 1:1.2, 1:1.4, 1:1.6)을 한 번에 학습·비교한다.
  - **채광 항은 넣지 않는다(μ = 0)**. 수요 D에 조명 전력이 들어 있어 채광 효과는 이미 반영된다.
  - 구현: `projects/05_bipv_mismatch/tide_policy/train_tide_policy.py`
  - 1/13 E+ 손익분기: 90°가 태양추적보다 나으려면 r > 0.026, 50° 버퍼가 90°보다 나으려면 r < 1.89.
    r ≤ 1 범위에서는 버퍼가 유리하다는 결론이 유지된다.
  - r이 결과를 바꾸는 경우는 P = D를 정확히 맞출 수 없을 때뿐이다(각도 격자·버퍼 묶음, 열 이월, 예측 오차).
    r < 1이면 예측 오차가 있을 때 각도를 낮게 두어 PV를 남기는 쪽으로 기운다.
  - r은 전기요금으로 정하지 않는다. 비용 = c_buy·부족 − c_sell·잉여로 두면 태양추적(PV 최대)이 항상 최적이 되어 각도 제어를 할 이유가 없어진다.
- **날짜별 정규화**: J_d(θ) / J_d(θ_ST). 부하가 큰 날이 학습을 지배하지 않게 하고, 값이 곧 태양추적 대비 개선율이 된다.
- **각도 이동 항**: 기존 라벨러의 λ·|Δθ|/10°와 같은 개념. 겨울 아침·오후 부족 시간대에 10분마다 각도가 흔들리던 문제를 억제한다.
  - L1 이동량은 θ_ST → 50° → 90°처럼 **한 방향으로 가는 버퍼에는 벌점을 더 주지 않는다**(총 이동량이 |90 − θ_ST|로 같음). 왕복 진동만 억제한다.
  - 따라서 버퍼를 막지 않으려면 L1을 유지하고, 각도 변경 횟수(L0)형 벌점은 쓰지 않는다.
- **평가 기간**: 하루 합계는 07시 ~ 다음 날 07시로 잡는다. 잉여 구간 각도가 오후·야간 HVAC에 주는 이월 효과(표의 14:10~19시 구매 79.58 → 75.53)까지 포함하기 위함이다.

## 2. 출력과 제약 처리

### 연속 각도 (권장)
하한 제약이 구조적으로 보장된다.

```python
z = tide(...)                                            # (B, 144, 1)
theta = theta_st + (90 - theta_st) * torch.sigmoid(z)   # 항상 [θ_ST, 90]
```

10° 격자 사이 비용은 선형 보간한다.

```python
# P_tab, D_tab: (B, 144, 10)  ← case2 각도별 PV, 수요. 학습 시 손실 계산에만 사용
i = (theta / 10).floor().clamp(max=8); f = theta / 10 - i
P = lerp(P_tab.gather(-1, i), P_tab.gather(-1, i + 1), f)
D = lerp(D_tab.gather(-1, i), D_tab.gather(-1, i + 1), f)
e = P - D
mis = w_sur * F.softplus(e * k) / k + w_def * F.softplus(-e * k) / k   # 0 근처를 부드럽게 한 hinge
move = (theta[:, 1:] - theta[:, :-1]).abs().sum(1)
loss = (mis.sum(1) + lam_move * move) / J_st_day                        # 날짜 정규화
```

### 조절 구간 마스크 (0절의 제어 구조 반영)
- 조절 구간 M_d = 태양추적 잉여 구간 {t : P_ST(t) > D_ST(t)}를 앞뒤로 k스텝 넓힌 범위. 버퍼가 잉여 구간 밖(예: 10:00~10:20)에 놓일 수 있기 때문이다.
- M_d 밖에서는 θ = θ_ST로 고정하고, 안에서만 위 sigmoid 출력을 쓴다.

```python
theta = torch.where(M, theta_st + (90 - theta_st) * torch.sigmoid(z), theta_st)
```

- M_d는 추론할 때 예측 공변량(예보 일사·기온)으로 계산한 θ_ST 기준 PV·수요 추정으로 정한다. 학습할 때는 `P_tab`, `D_tab`의 θ_ST 열로 정한다.
- k는 1시간(6스텝)부터 시작해 val에서 고른다.

### 이산 각도 (대안)
- 10-way logit을 출력하고 θ < θ_ST인 각도를 −∞로 마스킹한다.
- 손실은 기대비용 Σₐ softmax(ℓ)ₐ · Cₜ(a), 추론할 때는 argmax.
- 단점: 각도 이동 항이 기대값 위에서만 정의된다.

## 3. 입력(인수)

| 구분 | 내용 | 비고 |
|---|---|---|
| 미래 공변량 (예측일 하루치) | 일사(직달·확산), 외기온, 운량, sun_alt/az, 각도별 `cos_inc`, `poa`, 재실, 설정온도, 요일 | 현재 구성 유지 |
| 제약 겸 입력 | θ_ST(t) | 하한이자 입력 |
| 과거 공변량 | 기상, 실측 가능한 존 온도·PV·수요, 직전에 적용한 각도 | 10개 각도의 과거 성분은 제외 권장 (실제 운전에서 관측 불가, PLAN 미해결 문제) |
| 학습 전용 (입력 아님) | `P_tab`, `D_tab` (10각도 × 144) | 손실 계산에만 사용 |

과거 공변량: case2에는 각도를 바꿔가며 운전한 이력이 없다. 1차로는 태양추적 실행(또는 고정각 하나)의 존 온도·PV를 과거 입력으로 쓰고, 4-1의 반복 과정에서 실제 폐루프 이력으로 교체한다.

## 4. 주의할 점

1. **열관성 근사**: `D_tab`은 그 각도로 계속 운전한 열적 이력을 담고 있다. 각도를 바꾸는 운전에서는 해 진 후 HVAC(각도에 따라 18~29% 차이)가 정확하지 않다.
   - 손실을 하루 단위로 합산해 일 단위 효과를 최대한 반영한다.
   - 예측 스케줄로 E+ 폐루프 실행 → 결과를 학습 데이터에 추가 → 재학습을 1~2회 반복한다(DAgger 방식).
   - **이월 효과 주의**: 1/13 실험에서 잉여 구간 90°는 오후 구매를 4.05 kWh 줄였고, 50° 버퍼는 그중 0.57 kWh를 되돌렸다. 일정 각도 이력만 담은 `D_tab`으로는 이 효과가 정확히 잡히지 않으므로, 버퍼의 득실을 판단할 때는 E+ 폐루프 결과를 기준으로 삼는다.
2. **부족 구간 θ_ST 고정**: 2-3의 조절 구간 마스크로 기본 채택한다. 근거는 0절의 제어 구조다.
   기존 오라클에서 부족 구간의 구매 최소 각도가 10°/40°를 오가는 경우가 있었으므로, IWEC 평가기간에서 θ_ST 대비 구매 최소 각도의 regret을 확인해 마스크 밖 손실이 작은지 검증한다.
3. **기존 규칙과의 차이**: 2026-10-29 규칙은 잉여를 curtail하고 미스매치에 넣지 않았다. 이번 목적은 잉여에 벌점을 주므로, 잉여 구간이 90° 고정에서 "PV ≈ 수요가 되도록 버퍼 각도를 두는" 쪽으로 바뀐다. 채광 항(μ)의 유지 여부를 함께 정해야 한다.
4. **warm start**: 학습 초반에 기존 Viterbi 라벨에 대한 보조 손실(β·CE 또는 MSE)을 작게 넣고 점차 줄이면 수렴이 안정된다.
   "잉여 구간 90°" 규칙 스케줄을 warm start 라벨로 쓰는 것도 가능하다(TiDE가 여기서 버퍼를 덧붙이는 형태로 학습).
5. **대리 손실 검증**: 1/13 E+ 실행 3개(태양추적, 잉여 90°, 50° 버퍼)의 스케줄을 `P_tab`/`D_tab` 보간 손실로도 계산한다. 미스매치 순위(227.81 > 203.05 > 201.82)가 E+ 결과와 같은지 확인한 뒤 학습에 들어간다.

## 5. 미결정 사항
- ~~w_def : w_sur를 1:1로 유지할지~~ → 1:1로 시작한 뒤 부족 가중치를 올린다 (1절 가중치 결정 참조)
- 부족 가중치를 올리는 단계와 최종 r 선택 기준
- ~~채광 항(μ)을 넣을지~~ → 넣지 않음 (μ = 0)
- 조절 구간 확장폭 k (기본 6스텝)
- 끝 경계(13:30~14:10) 버퍼가 시작 경계만큼 효과가 있는지 (6-1 실험 후 결정)
