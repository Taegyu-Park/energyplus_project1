# 시계열 ML 학습 개념 Q&A

TiDE 기반 시계열 예측(BIPV Net Energy 최적화)을 이해하기 위해 정리한 질문과 답변입니다.

목차
1. 왜 (입력, 정답) 쌍을 만드는가
2. 배치와 은닉층
3. 목적함수(손실함수)의 종류와 선택 기준
4. 역전파는 왜 하는가, 기울기의 의미
5. 적절한 epoch 수
6. test 이후에 모델을 더 발전시킬 수 있는가

## 1. 왜 (입력, 정답) 쌍을 만드는가

### "미래 H스텝"은 test 데이터가 아닙니다

여기서 "미래"는 **그 윈도우 기준으로 뒤에 오는 구간**이라는 뜻이지, test 구간이라는 뜻이 아닙니다. train 구간 안에서도 어떤 시점을 기준으로 잡으면 그 뒤의 H스텝은 이미 관측된 값입니다.

```
전체 시계열:  [────── train ──────][── val ──][── test ──]

train 안의 윈도우 하나:
   ... t-3  t-2  t-1 | t  t+1  t+2 ...
       └ look-back L ┘ └ horizon H ┘
         입력 x            정답 y     ← 둘 다 train 구간 안의 이미 알고 있는 값
```

### 왜 쌍을 만드는가

모델 학습에는 **정답이 필요**합니다. 목적함수 L(예측, 정답)을 계산해야 하기 때문입니다. 그런데 시계열은 원래 "값이 시간순으로 나열된 한 줄"이라서 따로 붙어 있는 정답 라벨이 없습니다.

그래서 시계열 자신을 이용해 문제를 이렇게 바꿉니다.

> "과거 L스텝을 보고, 바로 이어지는 H스텝을 맞혀라"

윈도우를 한 칸씩 밀면 (입력, 정답) 쌍이 수만 개 생깁니다. 이렇게 시계열 예측이 일반적인 지도학습 문제가 됩니다.

### 각 구간에서 쌍이 쓰이는 방식

| 구간 | 윈도우의 정답 y | 쓰임 |
|---|---|---|
| train | 오차 계산 후 **가중치 업데이트에 사용** | 학습 |
| validation | 오차 계산만 하고 업데이트 안 함 | 설정 선택, early stopping |
| test | 오차 계산만 하고 업데이트 안 함 | 최종 성능 평가 |

즉 test 구간에도 (입력, 정답) 쌍을 똑같이 만들지만, 정답은 **평가용으로만** 씁니다. 실제 배포(미래 예측)에서는 정답이 아직 없으므로 모델은 입력만 받습니다.

### 주의: 구간 경계의 누수

윈도우의 입력 또는 정답이 train과 validation의 경계를 걸치면, 정답 구간의 일부가 다음 구간에 속하게 됩니다. 한쪽 윈도우의 정답이 다른 쪽 입력과 겹치면 정보가 새는 것입니다. 구간을 나눌 때는 윈도우가 경계를 넘지 않게 하거나, 경계에 L+H 정도의 간격을 두는 것이 안전합니다.

## 2. 배치와 은닉층

### 배치 (batch)

**가중치를 한 번 업데이트할 때 한꺼번에 계산에 쓰는 샘플 묶음**입니다.

- train 샘플이 10,000개이고 배치 크기가 64이면, 64개의 평균 손실로 기울기를 구해 가중치를 한 번 갱신합니다. 한 epoch는 약 157번의 갱신(step)입니다.
- 샘플 하나마다 업데이트하면 기울기가 너무 흔들리고 느립니다.
- 전체 데이터로 한 번에 계산하면 메모리가 부족하고, 업데이트 횟수가 적어 학습이 더딥니다.
- 배치는 그 중간입니다. 기울기가 어느 정도 안정적이고, GPU 병렬 계산을 활용할 수 있습니다.

배치 크기는 하이퍼파라미터입니다. 작으면 기울기에 잡음이 많고 업데이트가 잦고, 크면 안정적이지만 메모리가 많이 듭니다. 배치 크기가 바뀌면 같은 epoch라도 step 수가 달라집니다.

### 은닉층 (hidden layer)

신경망은 **입력층 → 은닉층(들) → 출력층** 구조입니다. 입력과 출력 사이에 있어서 직접 보이지 않는다고 해서 "은닉"이라고 부릅니다.

```
입력 x ─▶ [은닉층 1] ─▶ [은닉층 2] ─▶ 출력 ŷ
```

은닉층 하나가 하는 계산은 다음과 같습니다.

```
h = 활성화함수( W · x + b )
```

- **W, b:** 학습되는 가중치와 편향 (θ의 일부)
- **뉴런 수(hidden size):** 층이 만드는 값의 개수입니다. 층이 넓을수록 표현력이 큽니다.
- **활성화함수(ReLU 등):** 비선형성을 줍니다. 이게 없으면 층을 아무리 쌓아도 선형 변환 하나와 같아져서, 복잡한 패턴을 배울 수 없습니다.

층 수와 뉴런 수가 모델의 용량을 정합니다. 너무 작으면 패턴을 못 잡고(과소적합), 너무 크면 노이즈까지 외웁니다(과적합). 이 값들이 대표적인 하이퍼파라미터입니다. TiDE는 이런 MLP 블록(residual 연결 포함)을 쌓아 인코더와 디코더를 구성합니다.

## 3. 목적함수(손실함수)의 종류와 선택 기준

상세 표는 Notion의 BIPV 페이지 하위에 "시계열 ML 목적함수 정리" 페이지로 정리했습니다. 요약은 다음과 같습니다.

| 목적함수 | 핵심 특징 | 주로 쓰는 경우 |
|---|---|---|
| MSE | 큰 오차에 제곱 벌점, 미분이 매끄러움, 평균을 추정 | 기본값. 큰 오차를 특히 피하고 싶을 때 |
| RMSE | MSE의 제곱근, 원래 단위로 해석 가능 | 보고용 지표 |
| MAE | 오차에 비례하는 벌점, 이상치에 강건, 중앙값을 추정 | 이상치가 있는 데이터, 해석이 쉬운 지표 |
| Huber | 작은 오차는 MSE, 큰 오차는 MAE처럼 | MSE와 MAE의 절충 |
| MAPE | 실제값 대비 % 오차 | 값이 0에서 멀고 % 보고가 필요할 때 |
| sMAPE | MAPE의 비대칭 보완 | 스케일이 다른 계열 비교 |
| MASE | naive 예측 대비 오차 비율 | 서로 다른 시계열의 비교, 0 값이 있는 데이터 |
| Quantile (pinball) | 특정 분위수를 예측 | 불확실성 구간, 비대칭 비용 |
| NLL | 분포(평균, 분산)를 예측 | 확률적 예측 |
| CV(RMSE), NMBE | 건물에너지 모델 검증 지표 | ASHRAE Guideline 14 기준 비교 |

**이 프로젝트에서 특히 주의할 점:** PV 발전량은 밤에 0입니다. 실제값이 0인 시점에서 MAPE는 분모가 0이라 정의되지 않거나 폭발합니다. 이런 데이터는 MAE/MSE로 학습하고, 보고는 CV(RMSE)나 NMBE로 하는 것이 안전합니다.

## 4. 역전파는 왜 하는가, 기울기의 의미

### 먼저 순전파가 하는 일 정정

순전파는 "가장 낮은 곳으로 이동"하는 단계가 아닙니다. 순전파는 **현재 위치의 고도(손실값)를 재는 것**입니다.

| 단계 | 하는 일 | 지형 비유 |
|---|---|---|
| 순전파 + 손실 계산 | 지금 θ에서 L이 얼마인지 | 현재 고도를 읽는다 |
| 역전파 | 각 θ를 어느 쪽으로 움직여야 L이 줄어드는지 | 발밑의 경사를 읽는다 |
| 가중치 업데이트 | θ를 그 방향으로 조금 이동 | 한 걸음 내려간다 |

고도만 알아서는 어느 방향으로 가야 내려가는지 알 수 없습니다. **방향 정보가 필요하고, 그것이 기울기입니다.** 역전파는 이 기울기를 계산하는 알고리즘입니다.

### 기울기가 의미하는 것

기울기 ∂L/∂w는 이렇게 읽습니다.

> "다른 가중치는 그대로 두고 w만 아주 조금(+1 단위) 올렸을 때, 손실 L이 얼마나 변하는가"

- **부호:** 양수이면 w를 올릴수록 L이 커집니다. 그러면 w를 줄여야 합니다. 음수이면 반대로 w를 올려야 합니다.
- **크기:** 클수록 그 가중치가 손실에 민감하다는 뜻입니다. 급경사입니다. 0에 가까우면 평평한 곳이어서 바닥(또는 안장점)에 가깝습니다.
- **모든 가중치를 모으면:** 기울기 벡터 ∇L이 됩니다. 이것은 L이 **가장 가파르게 올라가는 방향**을 가리킵니다. 그래서 반대 방향(−∇L)으로 가면 가장 가파르게 내려갑니다. 이것이 경사하강법입니다.

### 숫자 예시 (가중치 1개)

모델: ŷ = w·x, 데이터: x=2, 정답 y=6, 손실: L=(ŷ−y)², 시작 w=1

1. 순전파: ŷ = 1×2 = 2, L = (2−6)² = **16**
2. 기울기: dL/dw = 2(ŷ−y)·x = 2×(−4)×2 = **−16**
   - 음수이므로 w를 올려야 L이 줄어듭니다. 그리고 크기가 크므로 아직 멀다는 뜻입니다.
3. 업데이트 (학습률 η=0.05): w = 1 − 0.05×(−16) = **1.8**
4. 다시 순전파: ŷ = 3.6, L = (3.6−6)² = **5.76** (16에서 감소)

이것을 반복하면 w가 3(=6/2)에 수렴하고 L이 0에 가까워집니다.

### 왜 "역"전파인가: 연쇄법칙

실제 신경망은 가중치가 수만~수백만 개이고 층이 겹겹이라서, 어떤 가중치가 L에 미치는 영향이 여러 층을 거칩니다.

```
w₁ → h₁ → h₂ → ŷ → L
```

w₁이 L에 미치는 영향은 "w₁→h₁의 변화율 × h₁→h₂의 변화율 × h₂→ŷ × ŷ→L"처럼 **변화율의 곱**(연쇄법칙)입니다. 출력쪽(ŷ→L)부터 계산해서 입력쪽으로 거슬러 가면서 곱해 나가면, 이미 계산한 앞부분을 재사용해서 **모든 가중치의 기울기를 한 번에** 구할 수 있습니다. 그래서 "역"전파입니다.

### 역전파 말고 다른 방법은 없나

가능은 합니다. 가중치를 하나씩 살짝 바꿔서 L이 변하는 것을 재면(수치 미분) 됩니다. 하지만 가중치가 N개이면 순전파를 N+1번 해야 합니다. 가중치가 100만 개면 한 번 업데이트에 순전파 100만 번입니다. 역전파는 순전파 1번과 비슷한 비용의 역방향 계산 1번으로 100만 개의 기울기를 모두 구합니다. 신경망 학습이 현실적으로 가능한 이유가 이것입니다.

PyTorch에서는 `loss.backward()` 한 줄이 역전파를 수행하고, `optimizer.step()`이 업데이트를 수행합니다.

## 5. 적절한 epoch 수

### 결론

**epoch 수를 정밀하게 맞추기보다, 충분히 크게 잡고 early stopping에 맡기는 것이 표준 방식입니다.** 적정 epoch은 데이터, 모델, 학습률, 배치 크기에 따라 달라서 미리 정하기 어렵고, early stopping이 이 값을 자동으로 찾아 줍니다.

### 권장 설정

```
max_epochs = 100 ~ 300   (충분히 크게)
patience   = 5 ~ 20      (validation이 개선 안 돼도 기다리는 epoch 수)
best 가중치 복원 = 켬     (멈춘 시점이 아니라 val 최저 시점의 가중치를 사용)
학습률 스케줄러 = 선택    (val 정체 시 학습률 감소. patience는 스케줄러보다 크게)
```

### 확인할 것

1. **early stopping이 실제로 작동했는가.** 최적 epoch가 max_epochs 근처라면 학습이 덜 된 것이므로 max를 늘립니다.
2. **patience가 너무 작지 않은가.** validation 곡선은 잡음이 있어서 잠깐 정체했다가 다시 내려갈 수 있습니다. 너무 작으면 일찍 멈춥니다.
3. **너무 크게 잡아도 문제가 없는가.** early stopping이 있으면 비용만 약간 늘 뿐 성능에는 해가 없습니다. 다만 계산 시간 상한은 둡니다.
4. **epoch 수끼리 비교하지 않기.** 배치 크기가 다르면 같은 epoch라도 업데이트 횟수가 달라서 의미가 다릅니다.

### 응용: 최적 epoch를 알아낸 뒤

early stopping으로 최적 epoch가 예를 들어 47로 나왔다면, 최종 모델은 train+validation을 합쳐 **47 epoch 고정**으로 다시 학습하기도 합니다. 데이터를 더 쓸 수 있지만, 이때는 validation이 없어서 감시가 안 되므로 상황에 따라 선택합니다. 시계열에서는 validation이 가장 최근 구간이라 이를 학습에 포함하면 이득이 큰 편입니다.

## 6. test 이후에 모델을 더 발전시킬 수 있는가

### 결론

**발전시킬 수 있습니다. 다만 그 순간부터 기존 test는 "한 번도 안 본 데이터"가 아니게 됩니다.**

"학습 종료 후 바로 test"는 한 번의 개발 사이클의 마지막 단계일 뿐이고, 모델 개선 자체가 금지되는 것은 아닙니다. 문제는 test 점수를 보고 개선 방향을 정하면 test가 validation처럼 선택에 쓰여서 낙관적으로 편향된다는 점입니다.

### 개선 방법

| 개선 축 | 예 |
|---|---|
| 데이터 | 더 많은 데이터, 이상치와 결측 처리, 새로운 공변량(일사량, 외기온, 재실 등) 추가 |
| 입력 설계 | look-back 길이 L, horizon H 조정, 스케일링 방식 |
| 모델 | 은닉층 크기와 층 수, dropout, 다른 모델과의 앙상블 |
| 목적함수 | MSE에서 Huber 또는 quantile로 변경, 가중치를 둔 손실 |
| 하이퍼파라미터 탐색 | Optuna 등으로 **validation 기준** 탐색 |
| 학습 방식 | 학습률 스케줄, 옵티마이저 변경, train+val 재학습 |

이 개선은 모두 **train과 validation 안에서** 반복하는 것이 원칙입니다.

### test를 다시 보고 싶다면 (선택지)

1. **새 test를 확보합니다.** 가장 깔끔합니다. 이 프로젝트에서 EnergyPlus로 다른 기상 연도나 다른 조건의 시뮬레이션을 더 만들 수 있다면, 모델 개발에 전혀 쓰지 않은 새 test 세트를 비교적 싸게 얻을 수 있습니다.
2. **기존 test를 validation으로 편입하고, 그 뒤의 새 구간을 test로 삼습니다.** 시계열에서는 시간이 지나 새로 쌓인 데이터를 test로 쓰는 방식입니다.
3. **walk-forward(rolling origin) 평가를 씁니다.** 시계열 교차검증입니다. 학습 구간을 점점 늘리거나 밀면서 여러 시점에서 미래를 예측하고 오차를 평균합니다. 한 구간에 의존하지 않아 편향과 우연의 영향이 줄어듭니다.
4. **정직하게 보고합니다.** 불가피하게 test를 여러 번 봤다면, 보고서에 몇 번 참조했고 어떤 결정에 영향을 줬는지 밝히고, 그 test 오차는 낙관적일 수 있다고 적습니다.

### 배포 이후

실제 운영에서는 시간이 지나 새 데이터가 쌓이면 **재학습**합니다. 환경이 바뀌면 모델 성능이 떨어지기도(distribution shift) 하므로, 새 데이터로 주기적으로 모니터링하고 갱신하는 것이 일반적입니다.

```
시계열 → 윈도우로 (입력, 정답) 쌍 생성 → train / val / test (시간순) 분할
   │
   ├─ [반복] train 배치: 순전파 → 손실 → 역전파(기울기) → 가중치 업데이트
   ├─ [매 epoch] val 오차 계산 → 개선 없으면 early stopping, 최적 가중치 보관
   ├─ [개선 루프] 하이퍼파라미터, 구조, 입력을 val 기준으로 조정
   └─ [마지막 1회] test 평가 → 보고
```
