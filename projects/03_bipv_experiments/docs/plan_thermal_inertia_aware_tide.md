# 열적 관성을 반영한 TiDE 각도 결정 계획

- 작성일: 2026-10-13
- 대상 모델: `bipv_experiments/idf/case3_v3_south_fixed.idf` (One-Diode PV, FullExterior)
- Net energy 정의: `냉방/3.0 + 난방/2.5 − PV(선택 각도 발전기만 합산)` (kWh)

---

## 0. 결론

**가능하다.** 다만 "임의 각도 시뮬레이션 데이터를 학습에 추가"하는 것만으로는 효과가 없다. 다음 세 가지가 함께 바뀌어야 한다.

1. **데이터**: 한 시뮬레이션 안에서 각도가 바뀌는 "동적 각도" 시뮬레이션을 만든다. 질문에서 제안한 방식이 이것이다.
2. **모델 입력**: 모델이 **과거 각도 이력**과 **앞으로의 각도 계획**을 입력으로 받아야 한다. 지금 TiDE는 각도를 입력으로 받지 않는다. 10개 출력 채널이 "그 각도를 1년 내내 유지했을 때"의 값이라, 동적 데이터를 넣어도 학습할 자리가 없다.
3. **결정 방식**: timestep마다 10개 중 `argmin`을 하면 관성을 알아도 쓸 수 없다. 오늘의 선택이 몇 시간 뒤 난방에 미치는 영향을 비교하려면, **각도 시퀀스(계획)를 평가해서 고르는 방식**(MPC, receding horizon)이 필요하다.

고정각 데이터와 동적 데이터를 함께 쓰는 방법은 아래 **잔차(residual) 구조**를 권장한다.

```
net_실제(t) = net_고정각[a_t](t)            ← 기존 TiDE (고정각 데이터로 학습)
            + Δ(각도 이력, 각도 계획, 날씨, t)  ← 새 관성 모델 (동적 데이터로 학습)
```

- 고정각 데이터에서는 각도 이력이 일정하므로 정의상 Δ = 0이다. 따라서 두 데이터셋이 하나의 식 안에서 일관되게 쓰인다.
- Δ는 "각도를 바꿨기 때문에 생기는 차이"만 담는다. 크기가 작고 구조가 단순해서 적은 동적 데이터로도 학습할 수 있다.

## 1. 현재 상황 (근거 수치)

`bipv_experiments/analysis/final_onediode_comparison.csv` (One-Diode, case3 fixed, 연간 kWh).

| 스케줄 | 스티칭 net | 실제 E+ net | 관성 손실 (net) | 난방 관성 (열) | 냉방 관성 (열) |
|---|---:|---:|---:|---:|---:|
| 태양추적 | −2,170 | −2,092 | +78 | +6 | +226 |
| TiDE 전략1 | −3,697 | **−3,167** | **+531** | **+1,161** | +199 |
| TiDE 전략2 | −3,044 | −2,735 | +309 | +704 | +82 |
| 고정 30° | −2,924 | −2,924 | 0 | 0 | 0 |

- **스티칭**: 고정각 결과에서 매 timestep 선택 각도의 값을 이어 붙인 값. TiDE가 학습 데이터 기준으로 "기대한" 값이다.
- **관성 손실** = 실제 E+ − 스티칭. 각도를 바꾼 이력 때문에 생긴 차이다.
- PV는 관성 효과가 없다. (Phase 0에서 모든 스케줄이 정확히 일치)

관찰:
- 태양추적은 각도 변화가 매끄럽고 야간 각도가 고정이라 관성 손실이 거의 없다(+78).
- TiDE 전략1은 각도를 자주, 크게 바꿔 **난방 관성 +1,161 kWh(열)** 이 생겼다. 기대한 이득(−3,697)의 약 14%를 잃었다.
- 위 One-Diode 결과에서는 S1이 태양추적보다 여전히 좋다. 태양추적보다 나쁘게 나온 결과가 다른 run(예: 과거 fig38 계열, 다른 IDF·PV 모델)이라면 그 run의 설정을 먼저 맞춰 비교해야 한다.
- **이 방법으로 회수할 수 있는 최대치는 전략1 기준 약 530 kWh(net)** 이다. 다만 관성을 알면 MPC가 "관성을 이용하는" 계획도 고를 수 있으므로, 스티칭 값보다 더 좋아질 수도 있다.

### 왜 고정각 데이터로는 관성을 배울 수 없나
고정각 run에서 각도 a의 라벨 `net_a(t)`는 "**과거 전체가 a였던 건물**"의 값이다. 벽체·실내 축열 상태가 a 이력에 맞춰져 있다. 동적 스케줄에서 t에 a를 고르면 축열 상태는 실제 과거 이력(다른 각도들)이 만든 상태이므로 값이 달라진다. 고정각 데이터에는 "이력 ≠ 현재 각도"인 샘플이 하나도 없어서, 어떤 모델로도 이 차이를 학습할 수 없다.

## 2. 전체 구조

```
[고정각 데이터]  c2_FE 10개 연간 run ──► 기존 TiDE: net_고정각[a](t+h) 예측 (10채널)
                                                   │
[동적 데이터]   case3 임의 각도 run ──► Δ(t) = net_실제 − net_고정각[a_t]  ─► 관성 모델 Δ̂ 학습
                                                   │
[결정]  후보 각도 계획 A = (a_t, …, a_{t+H}) ─► 점수 J(A) = Σ_h [ net̂_고정각[a_{t+h}] + Δ̂(이력, A) ]
        ─► J 최소 계획 선택 ─► 첫 1시간만 적용 ─► 1시간 뒤 다시 계획 (receding horizon)
```

---

## 3. 단계별 진행

### Step 1. 기존 데이터로 타당성 확인 (새 시뮬레이션 없음) ★ 먼저

이미 **동적 연간 run이 3개** 있다: `c3_FE_suntracking_od`, `c3_FE_tide_s1_od`, `c3_FE_tide_s2_od` (각 52,560 스텝). 고정각 기준값은 `analysis/c2_FE_fixed_angle_dataset.csv`에 있다.

1. 세 run에 대해 timestep별 Δ를 계산한다. 난방 Δ, 냉방 Δ, net Δ로 나눈다. (`final_onediode_comparison.py`의 스티칭 계산을 재사용)
2. Δ의 구조를 본다.
   - 각도 전환 직후 Δ가 커지고 몇 시간~며칠에 걸쳐 감쇠하는가? → 관성 시간상수. lookback 길이를 정하는 근거가 된다.
   - 어떤 전환이 손실을 만드는가? (예: 난방기 야간 0°↔주간 60°, 계절, 시각)
3. 간단한 모델(LightGBM 또는 작은 MLP)로 Δ를 예측해 본다. **leave-one-run-out**: 2개 run으로 학습하고 나머지 1개로 평가한다.
   - 입력 예: 현재 각도, 최근 1/6/24/72시간 평균 각도, 마지막 전환 이후 경과 시간, 전환 크기, 외기온·일사(과거/현재), 시각, day-of-year
4. 판정
   - 연간 Δ 합 예측 오차가 ±20% 이내이고 시간별 R²가 의미 있게 나오면 Step 2로 간다.
   - 예측이 안 되면, 이력 3개로는 전환 패턴이 부족한 것이다. 이때도 Step 2의 데이터가 필요하다.

### Step 2. 동적 각도 데이터 생성 (질문에서 제안한 시뮬레이션)

**어떤 스케줄을 만들까.** 10분마다 완전히 무작위로 바꾸는 방식은 쓰지 않는다. 실제로 쓰지 않을 패턴이고, 관성 효과가 서로 상쇄되어 학습이 어렵다. 대신 다음을 섞는다.

| 종류 | 내용 | 목적 |
|---|---|---|
| R1 구간 상수 무작위 | 각도를 무작위로 고르고 무작위 시간(1시간~3일, 로그 균등) 유지 | 다양한 전환 크기와 유지 시간 커버 |
| R2 주야 전환형 | 낮 각도 a, 밤 각도 b를 날마다 무작위로 정함. 난방기 비중 ↑ | 관성 손실의 주원인(난방기 주야 전환) 집중 학습 |
| R3 전략 섭동 | 태양추적·TiDE S1·oracle 스케줄에 ±10~30° 잡음, 일부 구간 고정각 치환 | MPC가 실제로 고를 영역 근처의 데이터 |
| R4 느린 변화 | 며칠~몇 주 단위로 천천히 바뀌는 각도 | 장기(며칠) 관성 확인 |

**실행 설정** (최종 비교 run과 같게)

- `idf`: `bipv_experiments/idf/case3_v3_south_fixed.idf`
- `solar_distribution: FullExterior`, `pv_simple: false` (One-Diode 필수)
- `ideal_sizing_from: bipv_experiments/sizing/case2_max_over_angles.eio`
- 스케줄 CSV 형식은 기존과 같다: `timestamp,optimal_angle` (10분 간격, 0~90° 10° 단위)
- PV는 `Facility Total Produced`가 아니라 **선택 각도 발전기의 `Generator Produced DC Electricity Energy` 합**으로 계산한다. (pv_simple 버그 이후 정한 규칙)

**규모와 비용**
- 연간 1회는 약 16시간 걸린다(`c3_FE_tide_s1_od`: 15h 46m). 병렬로 돌려도 1회와 시간이 비슷했다(Phase 0).
- 권장: **연간 run 12개 1배치** (R1×4, R2×4, R3×3, R4×1) → 약 63만 스텝, 약 1일.
- 연간 run을 권장하는 이유: 짧은 run은 웜업 때 첫날 각도로 축열 상태가 만들어진다. 그래서 앞 며칠을 버려야 하고, 버리는 비율만큼 비효율이다. 연간 run은 고정각 데이터와 날짜가 그대로 맞아 Δ 계산도 간단하다.
- 필요하면 상태 변수 출력을 추가한다. IDF에는 지금 존 온도 출력이 없다. `Zone Mean Air Temperature`, 남측 벽·창 `Surface Inside Face Temperature` 등을 출력하려면 **새 IDF 사본**을 `bipv_experiments/idf/`에 만든다. 원본 IDF는 수정하지 않는다.
  - 실제 건물에서는 실내 온도를 측정할 수 있으므로, 이 값을 입력으로 쓰면 "각도 이력"보다 직접적으로 축열 상태를 알려준다. (Step 3의 선택 입력)

**분할**: run 단위로 나눈다. 12개 중 2개(R1 1개, R2 1개)는 test 전용으로 둔다. 기존 3개 동적 run(태양추적/S1/S2)도 **test 전용**으로 둔다. 학습에 없던 실제 전략 스케줄에서 Δ를 맞히는지가 진짜 검증이다.

### Step 3. 관성 모델(Δ) 학습

**타깃**: `Δ_heat(t+h)`, `Δ_cool(t+h)` (h = 0..H−1). net Δ는 `Δ_cool/3 + Δ_heat/2.5`로 조합한다. PV는 관성이 없으므로 Δ에서 제외한다.

**입력**

| 구분 | 항목 | 비고 |
|---|---|---|
| past covariate | 과거 각도 (lookback L 스텝), 외기온, 직달·확산 일사 | 각도는 연속값(°/90)과 one-hot 모두 시험 |
| future covariate | **앞으로의 각도 계획** (H 스텝), 태양 고도·방위(sin/cos), 시각, day-of-year, 외기온·일사 | EPW 표준기상년이라 미래 날씨 사용 가능 |
| 파생 특성 | 현재 각도와 과거 평균 각도의 차, 마지막 전환 이후 경과 시간 | Step 1에서 효과가 확인된 것만 |
| (선택) 상태 | 과거 존 온도, 표면 온도 | Step 2에서 출력을 추가했을 때만 |

**모델**: 기존 TiDE 구조를 그대로 쓴다. past/future covariate 차원만 늘어난다(`tide_model.py` 구조 변경 없음). 학습 스크립트는 `train_tide.py`를 복사해 `bipv_experiments/`에 새로 만든다.
- lookback L: Step 1에서 본 관성 감쇠 시간으로 정한다. 후보는 144(1일) / 432(3일). 하루 이상 지속되면 1시간 평균으로 다운샘플한 긴 이력을 따로 넣는다.
- horizon H: 144(24시간). 저녁 각도가 다음 날 아침 난방에 주는 영향을 담기 위해서다.
- **고정각 앵커 샘플**: 고정각 run에서 뽑은 샘플(각도 이력 = 계획 = 상수, Δ = 0)을 일정 비율(예: 20%) 섞는다. 이렇게 하면 "안 바꾸면 손실 0"이라는 사실을 모델이 지키게 된다. 질문에서 말한 "**학습된 것과 고정각 결과를 동시에 고려**"가 이 부분에서 구현된다.

**대안: 단일 통합 모델.** 잔차 대신 `net_실제`를 직접 예측하는 모델 하나를 만들고, 고정각 데이터(각도 이력 = 상수)와 동적 데이터를 같은 형식으로 함께 학습하는 방법도 있다. 구조는 더 깔끔하다. 하지만 각도 간 net 차이가 공통 성분에 묻히는 기존 문제(`docs/plan_tide_improvement.md` 원인 1)가 그대로 남는다. 그래서 **1순위는 잔차 구조**로 하고, 통합 모델은 비교 실험으로 둔다.

**평가 지표 (test run 기준)**
- 시간별 Δ R², MAE
- run별 연간 Δ 합 오차. 예: S1 실제 난방 관성 +1,161을 맞히는가
- 순위 지표: 같은 시점의 서로 다른 후보 계획들에서 Δ의 대소 관계를 맞히는가 (결정에 필요한 것은 절댓값보다 순위다)

### Step 4. 각도 결정: timestep argmin → 계획 최적화(MPC)

매 1시간마다 다음을 한다.

1. **후보 계획 생성** (향후 24시간, 1시간 블록 단위 각도)
   - 기존 TiDE argmin 계획, 태양추적, 고정각 10개, 주야 2각도 조합(낮 a/밤 b, 100개)
   - 위 계획들의 평활화 버전 (최소 유지 시간 1·3·6시간)
   - Cross-Entropy Method(CEM): 블록별 각도 분포에서 수백 개 샘플 → 상위 10%로 분포 갱신 → 3~5회 반복
2. **점수**: `J(A) = Σ_h [ net̂_고정각[a_{t+h}](t+h) + Δ̂(이력, A)(t+h) ]`
   - 앙상블(시드 3~5개)의 Δ̂ 표준편차에 비례한 불확실성 벌점 `+ κ·σ`를 더한다. 학습 데이터에 없는 이상한 계획을 모델이 과대평가해서 고르는 것을 막는다.
3. J가 최소인 계획의 **첫 1시간만** 스케줄에 쓰고, 다음 시각에 실제 이력을 반영해서 다시 계획한다.
4. 출력은 기존과 같은 `timestamp,optimal_angle` CSV → `runner.py` + `bipv_schedule_plugin.py`로 그대로 시뮬레이션한다. 플러그인은 수정하지 않는다.

연산량: 1년 8,760회 × 후보 수백~수천 개. GPU 배치 추론이면 수 시간 이내로 예상한다.

**가장 단순한 중간 단계 (Step 4 이전 비교용)**: argmin에 전환 벌점 `λ·|a_t − a_{t−1}|`이나 최소 유지 시간을 붙인다. 관성 모델 없이도 관성 손실이 얼마나 줄어드는지 확인하는 기준선이다. λ는 Step 1의 Δ 모델로 오프라인 튜닝한다.

### Step 5. 폐루프 검증과 데이터 보강 (1~2회 반복)

1. Step 4 스케줄로 연간 E+ 실행 (One-Diode, FullExterior).
2. 비교 대상: 태양추적(−2,092), TiDE S1(−3,167), 전환 벌점 기준선(Step 4 중간 단계), 그리고 S1의 스티칭 값(−3,697).
3. 실행 결과의 실제 Δ와 모델 예측 Δ̂를 비교한다.
4. 크게 틀린 구간이 있으면 그 run을 동적 데이터에 추가해 재학습하고 한 번 더 실행한다. MPC가 고르는 영역의 데이터를 보강하는 것이다(DAgger 방식).

**성공 기준**
1. 오프라인: test run(태양추적/S1/S2)의 연간 Δ 합 오차 ±20% 이내
2. 시뮬레이션: net < −3,167 kWh (현재 S1보다 좋음)
3. 관성 손실(실제 − 스티칭)이 S1의 +531보다 작거나, 관성을 이용해 스티칭보다 좋음

## 5. 리스크와 대안

- **회수 가능한 크기가 작을 수 있다.** S1 기준 관성 손실은 net 약 530 kWh다. Step 1에서 Δ를 예측하기 어렵다면, 전환 벌점이나 최소 유지 시간 같은 단순 규칙이 비용 대비 더 나을 수 있다.
- **고정각 항의 오차가 더 클 수 있다.** 기존 분석에서 각도 간 net 차이 예측이 부정확했다(`plan_tide_improvement.md` 원인 1). Δ를 정확히 맞혀도 고정각 항이 틀리면 결정이 틀린다. 두 항의 오차를 따로 기록한다.
- **모델 악용(exploitation).** 최적화기는 모델이 과소평가하는 계획을 찾아간다. 앙상블 불확실성 벌점, R3(전략 섭동) 데이터, Step 5의 데이터 보강으로 대응한다.
- **긴 관성.** 난방 관성이 며칠 단위면 lookback 432 이상이 필요하고, 학습 샘플 수가 줄어든다. 이때는 긴 이력을 1시간 평균으로 요약해 넣는다.
- **대안: 강화학습.** `docs/bipv_drl_implementation_guide.md` 방향의 DRL은 관성을 자연스럽게 다룬다. 하지만 EnergyPlus를 환경으로 쓰면 에피소드 비용(연간 16시간)이 너무 크다. 이 문서의 "고정각 TiDE + Δ 모델"을 대리 환경으로 써서 RL을 학습하는 것은 Step 4의 대안으로 가능하다.
