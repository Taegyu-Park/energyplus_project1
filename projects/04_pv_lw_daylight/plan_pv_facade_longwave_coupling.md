## 1. 현재 상태 (문제 정의)

| 항목 | 현재 설정 | 열적 의미 |
|---|---|---|
| PV 객체 | `Generator:Photovoltaic`, `Decoupled` | 셀 온도는 계산하지만 건물로 열을 전달하지 않음 |
| PV 성능 | `PhotovoltaicPerformance:EquivalentOne-Diode` (Shinsung 390W) | NOCT 45/20 °C, 800 W/m²; Heat Loss Coef 80 W/m²K, Heat Capacity 50000 J/m²K (Decoupled에서 미사용) |
| PV가 붙은 객체 | `Shading:Building:Detailed` (`Shade_<면>_<각도>_<번호>`) | Construction 없음 → 열평형·온도 계산 없음. 그림자만 만듦 |
| 각도 구현 | 0~90°, 10° 간격 10세트, `TransSched_BIPV_A00`~`A90` 투과율 스케줄 on/off | 기하는 10세트지만 물리적 핀은 하나 |

→ 현재 BIPV 효과는 **발전량 + 일사 차폐**뿐이다. **PV가 데워져서 외피로 복사하는 열은 빠져 있다.**

## 2. 검토 후 기각한 방법

- **PV 모드를 `IntegratedSurfaceOutsideFace` 등으로 변경**: Integrated 모드는 PV가 붙은 표면의 열평형에 개입하는 방식인데, 차양 표면에는 열평형이 없다(열전달 표면만 허용될 것으로 보임 → 0단계에서 에러 여부 확인). 또 "떨어진 PV가 외피로 복사하는" 현실 상황과 물리적으로 맞지 않는다.
- **차양을 열전달 표면(BuildingSurface + 더미 존)으로 변경**: 핀마다 더미 존이 필요하고, 열전달 표면에는 투과율 스케줄이 없어 항상 그림자를 만든다. → 10개 각도 세트 on/off 구조가 깨진다.
- **`DecoupledUllebergDynamic`으로 열관성 반영**: 각도별 발전기가 각자 따로 온도 이력을 가져서, 각도가 바뀔 때 비물리적으로 점프한다.

## 3. 채택 방법: 외피가 PV 온도를 "보게" 한다

### 물리 경로
```
일사 → PV 흡수 → PV 온도 상승 (발전분 제외)
   ├─ 장파복사 → 외벽·창 외표면  ← 주 경로 (구현 대상)
   │     유리는 장파 불투과 → 유리 온도 상승 → 실내로 대류·복사
   └─ 대류 → 주변 공기 (개방형 루버라 대부분 흩어짐 → 선택 사항)
```

### 구조
```
[Decoupled PV]  셀 온도 계산 (기존 그대로, 추가 설정 없음)
      │  플러그인이 매 타임스텝 읽음: Generator PV Cell Temperature (현재 활성 각도의 발전기)
      ▼
[SurroundingSurfaces 온도 스케줄]  ← 플러그인이 actuate (각도별 뷰팩터 보정 포함)
      ▼
[외벽·창 외표면 장파 열평형] → 외표면 온도 → 실내 부하
```

- PV 쪽: **수정 없음** (`Decoupled` 유지, 셀 온도 출력만 사용)
- 차양 객체의 온도는 사용하지 않는다 (애초에 계산되지 않음).

### 각도별 뷰팩터 보정
IDF의 뷰팩터 필드는 고정값이므로 최대값 F_max로 고정해 두고, 유효온도로 보정한다.

```
T_eff⁴ = [F(θ)·T_pv⁴ + (F_max − F(θ))·T_bg⁴] / F_max
```
- F(θ): 각도 θ(0~90°, 10개)에서 PV 핀 ↔ 각 외벽·창 사이 뷰팩터. 오프라인으로 미리 계산해서 표로 둔다.
- T_bg: PV가 가리던 배경(하늘·지면)의 유효온도.
- 온도는 K 단위로 계산한 뒤 스케줄에는 °C로 넣는다.

### 열관성
- Timestep이 10분이고 PV 모듈 열 시정수는 대략 5~10분 → **1차 구현에서는 Decoupled 준정상 셀 온도를 그대로 사용**한다.
- 필요하면 2차로 플러그인에 핀당 온도 상태변수 1개짜리 RC 모델(C = 50000 J/m²K)을 추가한다. 상태변수를 핀 단위로 들고 가면 각도가 바뀌어도 열 이력이 유지된다.

## 7. 추가: PV 각도에 따른 조명 부하 (주광 연동)

### 문제
PV가 붙은 차양은 불투명이다. 각도가 낮아지면(닫히면) 실내 주광이 줄어서 조명 부하가 늘어야 하는데, 지금 모델은 이걸 반영하지 못한다.

### 현재 상태 — output만 추가해서는 안 되는 이유
- `Lights` (`SmallOffice Building_Lighting`, 6.896 W/m², SpaceList `SmallOffice Building`)는 **스케줄로만 동작**한다.
- IDF에 `Daylighting:Controls`, `Daylighting:ReferencePoint`가 **없다**.
- `Zone Lights Electricity Energy`는 이미 출력 중이지만, 각도와 무관하게 스케줄 값만 나온다. 0°와 90°에서 같은 값이 나온다.
- → 출력 변수만 추가해서는 각도 효과가 안 잡힌다. **주광 제어 객체 추가가 필요하다.** 새 기하나 플러그인 수정은 필요 없다.

### 방법
1. **`Daylighting:Controls` + `Daylighting:ReferencePoint` 추가** — **남쪽 존 2개에만 적용** (PV가 남측에만 있음)
   - 설정조도: **기본 400 lx (KS A 3011 조도분류 G 표준값)**. 민감도로 300 lx(G 최저)와 600 lx(G 최고)도 실행한다. 근거는 아래 "설정조도" 참고.
   - 대상 존: `BIPV_office_1_S` (1층), `BIPV_office_2_S` (2층)
     - 남측 외주부 존이고, 평면은 사다리꼴(y=0에서 x 0~32 m, y=5에서 x 5~27 m)로 깊이 5 m이다.
     - 남측 창 `..Wall_S_Glz0`는 x 0.32~31.68 m, 높이 0.29~3.96 m인 거의 전면 창이다.
   - Daylighting Method: `SplitFlux`
     - DElight는 외부 차양 처리가 제한적이라 쓰지 않는다.
   - 기준점: 존마다 1점, 조명 제어 비율 1.0
     - 1층 (16, 2.5, 0.85), 2층 (16, 2.5, 4.85) [m]
     - 존 중앙이자 깊이의 중간이다. 높이 0.85 m는 KS A 3011 4절의 작업면 높이(바닥 위 85 cm)를 따른다.
   - 제어 방식: `Continuous`, 최소 입력전력 비율 0.3 / 최소 광출력 비율 0.2 (E+ 기본값)
     - 민감도로 `ContinuousOff`(주광이 충분하면 완전 소등)도 검토한다.
   - Glare 계산: 이번 범위 밖이다 (선택).
   - `Lights`는 SpaceList 전체에 하나로 정의돼 있다. 주광 제어는 Daylighting:Controls가 걸린 남측 2개 존의 조명에만 적용되고, 나머지 존은 그대로 스케줄로만 동작한다. → `Lights` 객체는 수정할 필요가 없다.
2. **효과가 자동으로 연결되는 부분**
   - 조명 전력 감소량 → `Lights` 전력에 곱해진다 (Lighting Power Multiplier).
   - 조명 발열도 같이 줄어든다 → 냉난방 부하에 자동 반영된다. 즉 **조명·냉방·난방이 한 번에 일관되게 산정된다.**
3. **출력 변수 추가**
   - `Daylighting Reference Point 1 Illuminance` (TimeStep)
   - `Daylighting Lighting Power Multiplier` (TimeStep)
   - `Daylighting Reference Point 1 Daylight Illuminance Setpoint Exceeded Time` (선택)
   - 기존 `Zone Lights Electricity Energy` 유지 → 각도별 비교 지표로 사용

### 설정조도 (KS A 3011 원문 확인 완료, 2026-10-26)
- 동작 방식: 연속 디밍은 기준점 조도가 설정값이 되도록 (설정값 − 주광)만큼 조명을 켠다. 재실 스케줄 × 디밍 배율로 계산된다. 기준점 한 점 기준이며, 실 전체 평균 조도가 아니다.
- 출처: KS A 3011 「조도 기준」 (1998 제정, 최종 개정확인 2023-12-14). e-나라표준인증(standard.go.kr) 기계가독 원문에서 확인했다. 공모전 제출 시에는 같은 페이지의 "고시원문 보기" PDF로 쪽수를 다시 확인해서 인용한다.
- 조도 기준 위치: 4절 — 작업면은 바닥 위 85 cm(좌식 작업은 40 cm), 수평면 조도, **유지조도**(설비 초기값이 아님).
- 표 1 조도 분류 (최저–**표준**–최고, lx):
  | 분류 | 범위 | 활동 유형 |
  |---|---|---|
  | F | 150–**200**–300 | 고휘도 대비 혹은 큰 물체 대상의 시작업 수행 |
  | G | 300–**400**–600 | 일반 휘도 대비 혹은 작은 물체 대상의 시작업 수행 |
  | H | 600–**1000**–1500 | 저휘도 대비 혹은 매우 작은 물체 대상의 시작업 수행 |
- 표 7 사무실 (키보드, VDT 조명):
  - 로비·응접실·휴게실 F / 시청각실 F / 오프셋 인쇄와 복사실 F / 회의실 F / VDT가 있는 공간 F
  - 우편물 분류 G / 키보드 작업 G
  - **일반 개인 사무실, 회계 → 표 3 공공시설 "판독" 항목 참조**
- 표 3 공공시설 "판독" (일반 사무 작업에 해당):
  - G: 키보드 판독, 열전사 프린터, 헌 리본, 3회 이상 복사본, 연필(보통심), 칠판, 전화번호부, 지도, 6포인트 활자
  - F: CRT 화면, 잉크젯 프린터, 건조 인쇄(Xerograph), 볼펜, 신문 용지, 인쇄 원본, 8·10포인트 활자
  - H: 연필(경심), 재생 복사
- **채택: 조도분류 G의 표준값 400 lx** (일반 사무 작업 = 키보드·문서 판독 G 기준)
  - 민감도: 300 lx (G 최저) / 600 lx (G 최고)
  - 참고: EN 12464-1(500 lx)은 KS 표준값이 아니므로 본문 근거로 쓰지 않는다.
- 판단: 설정조도가 높을수록 "PV를 닫을 때의 조명 손해"가 커져서 최적 각도 판단에 직접 영향을 준다. → 기본값 1개 + 민감도 2개(G 범위 양 끝)로 결과의 강건성을 보여준다.

### 조명밀도 6.9 W/m²의 국내 근거 (2026-10-26 확인)
- 현재 값의 출처: 6.896 W/m² = 0.64 W/ft² → ASHRAE 90.1-2019 사무소(Building Area Method) 기준, DOE Small Office 프로토타입 값.
- 국내에는 **조명밀도 의무 상한값이 없다.** 대신 「건축물의 에너지절약설계기준」(국토교통부고시 제2026-360호, 2026-07-08 시행) 별지 제1호서식 에너지성능지표(EPI) 전기설비부문 1번 "거실의 조명밀도(W/㎡)"에서 배점으로 평가한다.
  | 조명밀도 [W/㎡] | <5 | 5~6 | 6~8 | 8~11 | 11~14 |
  |---|---|---|---|---|---|
  | 배점 (b) | 1.0 | 0.9 | **0.8** | 0.7 | 0.6 |
  - 기본배점 (a): 비주거 대형(3,000㎡ 이상) 9점, 소형(500~3,000㎡) 8점
  - → 6.9 W/㎡는 "6~8 미만, 0.8점" 구간이다. 국내 신축 사무소 수준으로 무리 없는 값이므로 **변경하지 않고 유지한다.** 값을 바꾸면 기존 결과를 모두 다시 돌려야 한다.
- 같은 고시에서 이번 주광 연동 모델링을 뒷받침하는 조항:
  - 의무사항: "일사광이 들어오는 창측의 전등군은 부분점멸이 가능하도록 설치한다" → 남측 존 주광 연동 디밍의 근거
  - 권장사항: "KS A 3011에 의한 작업면 표준조도를 확보" → 설정조도 400 lx(G 표준값)의 근거
  - EPI 전기 4번: 실내 조명설비 군별·회로별 자동제어 (전체 조명전력의 40% 이상)
- ECO2(에너지효율등급 평가 프로그램)는 조명밀도를 설계값으로 입력받는다. 용도 프로필의 요구조도 값은 이번에 확인하지 못했다.

### 사전 검증 필요 (중요)
EnergyPlus는 주광계수(daylight factor)를 미리 계산해 두고 쓴다. 그래서 **매 타임스텝 바뀌는 차양 투과율 스케줄(각도 on/off)이 주광 계산에 제대로 반영되는지** 확인해야 한다.
- 테스트 A: 각도를 0°로 고정 vs 90°로 고정 → 기준점 조도가 확실히 달라지는지 확인
- 테스트 B: 플러그인으로 각도를 시간마다 바꾸는 실행 → 해당 시각의 조도가 테스트 A의 고정 실행 값과 일치하는지 확인
- 반영이 안 되면 대안을 검토한다.
  - 각도별 고정 실행 10회로 조명 배율 표를 만들고, 플러그인에서 `Lights` 전력을 actuate한다.
  - 또는 주광계수를 각도별로 따로 쓰는 다른 우회 방법을 찾는다.
- 반사광: PV 표면 반사율은 기본값(0.2)이다. 반사 포함 계산(`Calculate with reflections`)은 기본 off이므로 1차에서는 무시한다.

### 계획에서 바뀐 점
- **PV 셀 온도 센서:** case2 발전기 이름의 첫 숫자는 단 번호가 아니다(예: `PV_3_30_01`은 2단). 그래서 단은 차양 기하(경첩 높이)로 판별한다.
- **T_eff 시점:** PV 셀 온도는 직전 스텝 값이다(PV는 HVAC 이후 계산됨). 각도가 바뀐 스텝에는 직전 각도의 발전기 온도와 현재 각도의 뷰팩터를 쓴다.
- **case3 조명 = case2 짜깁기 배율 표 (7절 "사전 검증" 결과):** case3에 Daylighting:Controls를 넣으면 PV 루버를 아예 무시한다. 0° 시간대에도 조도가 0이 되지 않고, 정오 값이 case2 90°의 약 4배다. IDF 투과율 스케줄이 전부 1.0이라 플러그인이 실행 중에 바꾸는 값을 주광 계산이 모르기 때문이다. 주광은 열적 이력이 없으므로, 같은 설정(FullExterior, 그림자 매 타임스텝, DetailedSky)의 case2 각도별 결과를 짜깁기해도 정확하다. case3 플러그인이 남측 존 `Lights` Electricity Rate를 `설계 전력 × 스케줄 × 배율[각도, 스텝]`로 actuate한다.
- **배율 표 실행만 PV Simple 모델 사용:** FullExterior 90°에서 One-Diode(Eg 1.12)가 발산하기 때문이다. Decoupled라 부하·조명에는 영향이 없다.
